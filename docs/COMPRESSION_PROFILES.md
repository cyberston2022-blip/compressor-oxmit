## ۱) فهرست کامل پروفایل‌ها (۱۶ پروفایل)

| # | کلید | نام نمایشی | موتور | مخاطب | توضیح |
|---|---|---|---|---|---|
| 1 | `edu480` | 🟢 سبک | x264 CRF25 + مقیاس 480p | **کاربر عادی** (پنل اصلی) | سبک‌ترین گزینهٔ استاندارد؛ صدا بهینه‌شده برای گفتار |
| 2 | `edu360` | 🟡 متعادل | x264 CRF26 + مقیاس 360p | **کاربر عادی** (پنل اصلی) | حجم کمتر از سبک، کیفیت متعادل |
| 3 | `custom` | 🎯 حجم دلخواه | x264 ABR+VBV تک‌پاس | **همه** (کاربر: دکمهٔ پنل، ادمین: گرید) | بیت‌ریت از حجم هدف محاسبه می‌شود (۵MB تا ۸GB) |
| 4 | `level` | 🎚 درجه ۱–۲۰ | x264 CRF18–28 (نقشهٔ درجه) | **کاربر عادی** (پنل اصلی) | CRF محتواآگاه؛ درجه بالاتر = حجم کمتر |
| 5 | `educational` | آموزشی ( legacy) | x264 + 480p | فقط گرید ادمین | نام قدیمی؛ به `edu480` نگاشت می‌شود |
| 6 | `balanced` | Balanced | x264 CRF22 veryfast | فقط گرید ادمین | تعادل کلاسیک کیفیت/حجم/سرعت |
| 7 | `highq` | High quality | x264 CRF19 faster | فقط گرید ادمین | حفظ کیفیت بصری بالا |
| 8 | `small` | Smaller | HEVC CRF27 faster | فقط گرید ادمین | حجم کمتر با H.265 |
| 9 | `maxcomp` | Max compression | HEVC CRF30 superfast | فقط گرید ادمین | کمترین حجم، کندترین |
| 10 | `tgcompat` | Telegram compat | x264 High + AAC + faststart | فقط گرید ادمین | حداکثر سازگاری پخش |
| 11 | `r1080` | کاهش به ۱۰۸۰p | x264 + scale (بدون upscale) | فقط گرید ادمین | هیچ‌وقت بزرگ‌نمایی نمی‌کند |
| 12 | `r720` | کاهش به ۷۲۰p | x264 + scale | فقط گرید ادمین | — |
| 13 | `r480` | کاهش به ۴۸۰p | x264 + scale | فقط گرید ادمین | — |
| 14 | `rostam` | ⚔️ رستم و سیاوش | HEVC CRF32/34 + 360p + denoise + mono | کاربر (فقط وقتی heuristic «از قبل فشرده» بگیرد) + گرید ادمین | فوق‌متراکم برای ویدیوهای از-قبل-فشرده |
| 15 | `remux` | 📥 ارسال اصلی | stream-copy بدون انکود | کاربر (مسیر از-قبل-فشرده) + گرید ادمین | جابه‌جایی کانتینر به MP4+faststart — چند ثانیه |
| 16 | `level265` | (داخلی) | HEVC CRF+5 superfast | **داخلی** — هرگز مستقیم انتخاب نمی‌شود | ارتقای خودکار وقتی x264 به منبع باخت (no-gain) |
| 17 | `custom_2pass` | (داخلی، غیرفعال) | x264 دوپاس | **غیرقابل دسترس** | decision-engine `two_pass=False` اجباری کرده؛ تک‌پاس جایگزین شده |

> قانون طلایی همهٔ پروفایل‌های مقیاس‌دار: **هرگز بزرگ‌نمایی نمی‌کنند** — اگر منبع کوچک‌تر از هدف باشد، `resolve_variant` پروفایل پایین‌تر یا balanced را برمی‌دارد.

## ۲) دسترسی بر اساس نقش

### 👤 کاربر عادی (۴ دکمهٔ پنل + ۲ زمینه‌ای)
| پروفایل | کجا دیده می‌شود |
|---|---|
| 🟢 سبک (`edu480`) | دکمهٔ اول کارت اطلاعات — همراه تخمین ~٪ کاهش و ~MB |
| 🟡 متعادل (`edu360`) | دکمهٔ دوم — همراه تخمین |
| 🎯 حجم دلخواه (`custom`) | دکمهٔ سوم → انتخاب سریع 50/100/200/400MB یا عدد دلخواه |
| 🎚 درجه ۱–۲۰ (`level`) | دکمهٔ چهارم → ارسال عدد |
| ⚔️ رستم (`rostam`) | فقط وقتی تحلیل بیت‌ریت بگوید «این ویدیو از قبل فشرده شده» |
| 📥 ارسال اصلی (`remux`) | همان کارت — بدون افت کیفیت، چند ثانیه |

+ ♻️ اگر نسخهٔ کش‌شده موجود باشد، کارت پیشنهاد کش قبل از انکود می‌آید (دریافت فوری یا پروفایل پایین‌تر).

### ⚙️ ادمین (هر ۴ دکمهٔ کاربر + گرید کامل)
همهٔ ۱۶ پروفایل از طریق گرید `pk:` روی کارت اطلاعات — **منهای آن‌هایی که Owner فعال نکرده باشد** (گیت `compression.use`). ادمین علاوه بر آن‌ها برندینگ شخصی (تامبنیل/واترمارک/کپشن) روی خروجی‌های خودش می‌گیرد.

## ۳) 🏆 بهترین عملکردها (اندازه‌گیری‌شده، نه حدسی)

### دادهٔ مبنا
- بنچمارک رسمی ریپو: `reports/optimization/benchmark_results.csv` — ۲۴ کانفیگ روی منابع Film/Screen 1080p، با SSIM/PSNR
- بنچمارک سرور 2026-11-05: x264/x265 با پارامترهای production (threads=6، pools=6:frame-threads=3)

### 🥇 برندگان هر دسته

| دسته | برنده | عدد اندازه‌گیری‌شده |
|---|---|---|
| **کمترین حجم مطلق** | 🥇 `maxcomp` (x265 superfast CRF30) | **۸۰٪ کاهش** (9.63MB از 48.8MB) با 26.3 FPS — Pareto-optimal برای حجم |
| **بهترین تعادل حجم/کیفیت** | 🥇 `small` (x265 superfast CRF27) | 16.3MB با SSIM 0.7959 — Pareto-optimal برای تعادل |
| **سریع‌ترین انکود باکیفیت (x264)** | 🥇 `balanced/level` (x264 veryfast CRF23) | 40.6 FPS — Pareto-optimal برای سرعت |
| **سریع‌ترین مطلق** | 🥇 `remux` | **۵۰ برابر سریع‌تر** (0.63s)، SSIM 1.0 — فقط وقتی کدک‌ها سازگار باشند |
| **کمترین زمان دیواری (مقیاس‌دار)** | 🥇 `edu360` / `edu480` | 480p: 5.04s در برابر 23.4s بدون مقیاس — پیکسل کمتر = غالب مطلق |
| **دقت حجم هدف** | 🥇 `custom` تک‌پاس ABR+VBV | خطای هدف فقط **−۱.۱۱٪** روی فیلم (دوپاس از خط تولید حذف شده) |
| **منابع از-قبل-فشرده** | 🥇 `rostam` | تنها پروفایل با denoise + mono voice — با محافظ no-gain |

### ❌ حذف‌شده‌ها (توسط تحلیل Pareto)
- `x265 medium CRF28`: توسط superfast CRF30 اکیداً مغلوب است — **۲۲٪ فایل بزرگ‌تر و ۲.۱۷× کندتر** با کیفیت آماری معادل → از production حذف شد.
- `custom_2pass`: خطای −۱۰۰٪ در تست (اجرای شکسته) و decision-engine تک‌پاس را اجباری کرده → غیرقابل دسترس.
- scale-به-720p برای متن: «فایل بزرگ‌تر، متن تارتر» → مقیاس پایین‌تر (edu) ارجح است.

### 📌 نکتهٔ عملکردی مهم
۹۹.۷٪ زمان پردازش = CPU انکود (گزارش forensic). بنابراین سریع‌ترین راه برای کاربر: **پروفایل مقیاس‌دار پایین‌تر** (edu360/edu480) یا **remux** — و برای ادمین: `maxcomp` فقط وقتی حجم مطلق مهم‌تر از زمان است.

## ۴) 🏆 جمع‌بندی — پیشنهاد بر اساس نقش

### برای کاربر عادی
| نیاز | انتخاب |
|---|---|
| «فقط سریع کوچکش کن» | 🟢 **سبک (edu480)** |
| «کیفیت مهم‌تره ولی حجمم کم بشه» | 🟡 **متعادل (edu360)** |
| «حجم دقیق X می‌خوام» | 🎯 **حجم دلخواه** |
| «خودم تنظیم می‌کنم» | 🎚 **درجه ۱–۲۰** (۱۵ ≈ نقطهٔ تعادل) |
| «ویدیوم از قبل فشرده‌ست» | ⚔️ **رستم** یا 📥 **remux** |

### برای ادمین
| نیاز | انتخاب برنده |
|---|---|
| **کمترین حجم ممکن** | `maxcomp` — ۸۰٪ کاهش (برندهٔ مطلق بنچمارک) |
| **تعادل هوشمند HEVC** | `small` — Pareto تعادل |
| **سرعت + کیفیت x264** | `balanced` (veryfast CRF22/23 — Pareto سرعت) |
| **بایگانی/کیفیت بالا** | `highq` |
| **کاهش رزولوشن کنترل‌شده** | `r720`/`r480` (هرگز upscale نمی‌کنند) |
| **سازگاری تضمینی پخش** | `tgcompat` |
| **سریع‌ترین (بدون انکود)** | `remux` — ۵۰×، بی‌افت |
| **ادغام چند ویدیو** | `/merge` → سپس فشرده‌سازی از طریق همین پروفایل‌ها |
